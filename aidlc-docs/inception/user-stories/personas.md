# 사용자 페르소나 (User Personas)

## 1. 임베디드 C/C++ 시스템 엔지니어 — "Min-soo"

- **역할 및 배경**:
  - 임베디드 Linux 상에서 C/C++ 미션 크리티컬 데몬 및 런타임을 개발·유지보수하는 10년 차 시스템 엔지니어.
  - 디버거(GDB) 연결이나 프로세스 중단이 불가능한 실제 운영 환경에서 메모리 손상, 누수, 데드락, 크래시 원인을 추적해야 함.
- **주요 목표**:
  - 타깃 프로세스에 정지(zero-stop)나 성능 저하를 일으키지 않고 신속하게 진단 수행.
  - 단순 추측이나 LLM의 환각이 아닌, DWARF 디버그 정보 및 실제 메모리 주소/소스 라인(`file:line`)과 1:1로 매핑되는 결정론적 결함 원인 규명.
  - 한눈에 원인을 파악할 수 있는 시각적 인시던트 리포트 및 자연어 원인 해설 확보.
- **불편 사항 (Pain Points)**:
  - 잘못된 증거 수집으로 인해 멀쩡한 코드를 결함으로 오탐(False Positive)하거나, 원격 장비 상태가 오염되는 현상.
  - 신뢰할 수 없는 프로세스 식별로 인해 PID 재사용 시 이전 프로세스의 오래된 증거가 섞여 진단이 왜곡되는 문제.
- **관련 스토리**: US-TRUST-001, US-TRUST-002, US-EXPLAIN-001, US-BENCH-001

## 2. MCP 기반 AI 코딩 에이전트 — "AI Agent" (Cursor / Claude)

- **역할 및 배경**:
  - Model Context Protocol (MCP) 표준을 통해 `dynamic-state-mcp` 서버와 stdio로 통신하며 자율적으로 장애를 분석하고 코드를 수정하는 AI 어시스턴트.
- **주요 목표**:
  - `runtime_diagnose_process`, `runtime_explain_process_behavior` 등의 MCP 도구를 정해진 규약에 따라 호출.
  - 도구로부터 구조화되고 일관된 JSON 형식의 `DiagnoseResult` 및 증거 참조 체인을 반환받아 명확한 진단 결론 도출.
  - 정보 부족 시 침묵하거나 추측하지 않고, 명시적인 기권(abstention) 및 `INCONCLUSIVE`/`not_covered` 응답을 수신하여 안전하게 행동.
- **불편 사항 (Pain Points)**:
  - 도구의 입력 검증이 느슨하여 비정상 파라미터가 조용히 성공으로 처리되거나 내부 상태를 손상시키는 경우.
  - LLM의 자연어 생성이 결정론적 진단 코어의 판정이나 증거를 임의로 왜곡할 위험.
- **관련 스토리**: US-TRUST-001, US-TRUST-004, US-EXPLAIN-001, US-PROCESS-001

## 3. 품질 및 보안 감사자 — "Jin-woo"

- **역할 및 배경**:
  - 시스템 보안 및 신뢰성 표준 준수를 검증하고, CI/CD 파이프라인의 품질 게이트를 관리하는 플랫폼 엔지니어.
- **주요 목표**:
  - 모든 진단 증거와 영수증(Attestation)이 조작되거나 재사용되지 않고 엄격한 보안 경계 내에서 관리됨을 보증.
  - 지속성 저장소 파일(`0600`), 디렉터리(`0700`), lock 파일의 소유권 및 심볼릭링크 공격 방어 체계 감사.
  - 벤치마크 결과가 git dirty 상태 없이 clean commit에서 정확히 재현되는지 확인.
- **불편 사항 (Pain Points)**:
  - 실패하거나 거부된 증거가 하류 진단 결론이나 리포트에 섞여 들어가는 보안 경계 누수.
  - 단위 테스트만 통과한 상태에서 실제 시스템 신뢰 경계 검증이 누락되는 관행.
- **관련 스토리**: US-TRUST-003, US-TRUST-004, US-TRUST-005, US-TRUST-006, US-TRUST-007, US-BENCH-001, US-PROCESS-001
