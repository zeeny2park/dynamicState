# 오류 처리 및 복구 절차 (Error Handling and Recovery Procedures)

## 일반 오류 처리 원칙

### 오류가 발생하면
1. **오류 파악**: 무엇이 잘못되었는지 명확히 밝힌다
2. **영향 평가**: 진행을 막는 오류인지, 우회할 수 있는 오류인지 판단한다
3. **알림**: 사용자에게 오류와 선택지를 알린다
4. **해결책 제시**: 오류를 해결하거나 우회할 명확한 절차를 제시한다
5. **기록**: 오류와 해결 내용을 `audit.md` 에 기록한다

### 오류 심각도 수준

**Critical (치명)**: 워크플로를 계속할 수 없음
- 필수 파일 또는 산출물 누락
- 처리할 수 없는 잘못된 사용자 입력
- 파일 작업을 막는 시스템 오류

**High (높음)**: stage 를 계획대로 끝낼 수 없음
- 필수 질문에 대한 답이 불완전함
- 서로 모순되는 사용자 응답
- 이전 stage 에서 와야 할 의존 항목 누락

**Medium (중간)**: 우회책으로 stage 를 계속할 수 있음
- 선택 산출물 누락
- 치명적이지 않은 검증 실패
- 부분 완료 가능

**Low (낮음)**: 진행을 막지 않는 사소한 문제
- 서식 불일치
- 선택 정보 누락
- 진행을 막지 않는 경고

## Stage 별 오류 처리

### Workspace Detection 오류

**오류**: 작업 공간 (workspace) 파일을 읽을 수 없음
- **원인**: 권한 문제, 디렉터리 누락
- **해결**: 사용자에게 작업 공간 경로와 권한 확인을 요청한다
- **우회**: 사용자가 제공한 정보만으로 진행한다

**오류**: 기존 `aidlc-state.md` 가 손상됨
- **원인**: 수동 편집, 이전 실행이 끝나지 않음
- **해결**: 새로 시작할지, 복구를 시도할지 사용자에게 묻는다
- **복구**: 백업을 만들고 새 상태 파일을 시작한다

**오류**: 필요한 stage 를 판단할 수 없음
- **원인**: 사용자 정보 부족
- **해결**: 의도와 범위에 대해 확인 질문을 한다
- **우회**: 기본값으로 포괄적인 실행 계획을 쓴다

### Requirements Analysis 오류

**오류**: 사용자가 서로 모순되는 요구사항을 제시함
- **원인**: 이해 부족, 요구 변경
- **해결**: 모순을 해소할 후속 질문을 만든다
- **진행 금지**: 모순이 해소될 때까지

**오류**: 요구사항 문서를 변환할 수 없음
- **원인**: 지원하지 않는 형식, 손상된 파일
- **해결**: 지원하는 형식으로 요구사항을 달라고 사용자에게 요청한다
- **우회**: 사용자의 말로 된 설명을 바탕으로 작업한다

**오류**: 검증 질문에 대한 답이 불완전함
- **원인**: 사용자가 질문을 건너뜀, 무엇을 답해야 할지 불분명함
- **해결**: 답하지 않은 질문을 강조하고 예시를 제공한다
- **진행 금지**: 필수 질문에 모두 답할 때까지

### User Stories 오류

**오류**: 요구사항을 story 에 연결할 수 없음
- **원인**: 요구사항이 너무 모호함, 기능 세부 내용 누락
- **해결**: Requirements Analysis 로 돌아가 명확히 한다
- **우회**: 있는 정보로 story 를 만들고 미완성으로 표시한다

**오류**: 사용자가 story 계획 질문에 모호하게 답함
- **원인**: 선택지가 불분명함, 결정이 복잡함
- **해결**: 구체적인 예시를 담은 후속 질문을 추가한다
- **진행 금지**: 모호함이 해소될 때까지

**오류**: story 생성 계획에 완료되지 않은 step 이 있음
- **원인**: 실행 중단, step 건너뜀
- **해결**: 완료되지 않은 첫 step 부터 재개한다
- **복구**: 완료된 step 을 검토하고 체크포인트부터 이어 간다

### Application Design 오류

**오류**: 아키텍처 결정이 불분명하거나 모순됨
- **원인**: 모호한 답, 충돌하는 요구사항
- **해결**: 결정을 명확히 할 후속 질문을 추가한다
- **진행 금지**: 결정이 명확해지고 문서화될 때까지

**오류**: 서비스 · unit 개수를 정할 수 없음
- **원인**: 경계에 대한 정보 부족
- **해결**: 배포, 팀 구조, 확장에 대해 구체적으로 질문한다
- **우회**: 기본값으로 모놀리스를 택하고 나중에 바꿀 수 있게 둔다

### 설계 오류

**오류**: unit 간 의존 관계가 순환함
- **원인**: 경계 정의 미흡, 강한 결합
- **해결**: 순환 의존을 찾아내고 리팩터링을 제안한다
- **복구**: unit 경계를 수정해 순환을 끊는다

**오류**: unit 설계 계획에 빠진 step 이 있음
- **원인**: 계획 생성 미완료, 템플릿 오류
- **해결**: 필요한 step 을 모두 넣어 계획을 다시 만든다
- **복구**: 기존 계획에 빠진 step 을 추가한다

**오류**: 설계 산출물을 만들 수 없음
- **원인**: unit 정보 누락, 요구사항 불분명
- **해결**: Units Generation 으로 돌아가 unit 정의를 명확히 한다
- **우회**: 부분 설계를 만들고 빈 곳을 표시한다

### NFR 구현 오류

**오류**: 기술 스택 선택이 서로 호환되지 않음
- **원인**: 충돌하는 요구사항, 플랫폼 제약
- **해결**: 호환되지 않는 지점을 강조하고 사용자에게 선택을 요청한다
- **진행 금지**: 호환되는 선택이 정해질 때까지

**오류**: 조직의 제약을 충족할 수 없음
- **원인**: 네트워크 제한, 보안 정책
- **해결**: 제약을 문서화하고 사용자에게 우회 방법을 묻는다
- **상향 보고 (Escalation)**: 설정에 사람의 개입이 필요할 수 있음

**오류**: NFR 구현 step 에 사람의 작업이 필요함
- **원인**: AI 가 할 수 없는 작업 (네트워크 설정, 자격 증명)
- **해결**: **HUMAN TASK (사람 작업)** 으로 명확히 표시하고 안내를 제공한다
- **대기**: 진행 전에 사용자 확인을 기다린다

### Code Generation 계획 오류

**오류**: 코드 생성 계획이 불완전함
- **원인**: 설계 산출물 누락, 요구사항 불분명
- **해결**: 설계 stage 로 돌아가 산출물을 완성한다
- **복구**: 있는 정보로 계획을 만들고 빈 곳을 표시한다

**오류**: unit 의존 관계가 충족되지 않음
- **원인**: 의존하는 unit 이 아직 생성되지 않음
- **해결**: 의존 관계를 지키도록 생성 순서를 바꾼다
- **우회**: 의존 대상을 stub 으로 두고 생성한 뒤 나중에 통합한다

### Code Generation 오류 (Part 2: Code Generation)

**오류**: 어떤 step 의 코드를 생성할 수 없음
- **원인**: 설계 정보 부족, 요구사항 불분명
- **해결**: 해당 step 을 건너뛰고 미완료로 기록한 뒤 계속한다
- **복구**: 정보를 더 모은 뒤 그 step 으로 돌아간다

**오류**: 생성된 코드에 문법 오류가 있음
- **원인**: 템플릿 문제, 언어별 문제
- **해결**: 문법 오류를 고치고 필요하면 다시 생성한다
- **검증**: 진행 전에 코드가 컴파일되는지 확인한다

**오류**: 테스트 생성 실패
- **원인**: 복잡한 로직, 테스트 프레임워크 설정 누락
- **해결**: 기본 테스트 구조를 만들고 수동 완성 대상으로 표시한다
- **우회**: 테스트 없이 진행하고 Operations phase 에서 추가한다

### Operations 오류

**오류**: 빌드 도구를 판단할 수 없음
- **원인**: 특이한 프로젝트 구조, 여러 빌드 시스템
- **해결**: 빌드 도구와 명령을 지정해 달라고 사용자에게 요청한다
- **우회**: 일반적인 안내를 제공하고 사용자가 맞춰 쓰게 한다

**오류**: 배포 대상이 불분명함
- **원인**: 여러 환경, 복잡한 인프라
- **해결**: 배포 대상과 방식을 지정해 달라고 사용자에게 요청한다
- **우회**: 흔히 쓰는 플랫폼 기준 안내를 제공한다

## 복구 절차

### Stage 부분 완료

**상황**: stage 실행 도중 중단됨

**복구 단계**:
1. stage 계획 파일을 불러온다
2. 마지막으로 완료된 step (마지막 [x] 체크박스) 을 찾는다
3. 다음 미완료 step 부터 재개한다
4. 이전 step 이 모두 실제로 완료되었는지 확인한다
5. 평소대로 실행을 이어 간다

### 상태 파일 손상

**상황**: `aidlc-state.md` 가 손상되었거나 앞뒤가 맞지 않음

**복구 단계**:
1. 백업 생성: `aidlc-state.md.backup`
2. 실제로 어느 stage 에 있는지 사용자에게 묻는다
3. 상태 파일을 처음부터 다시 만든다
4. 기존 산출물을 기준으로 완료된 stage 를 표시한다
5. 현재 stage 부터 재개한다

### 산출물 누락

**상황**: 이전 stage 의 필수 산출물이 없음

**복구 단계**:
1. 어떤 산출물이 없는지 파악한다
2. 다시 만들 수 있는지 판단한다
3. 가능하면: 해당 stage 로 돌아가 산출물을 다시 만든다
4. 불가능하면: 사용자에게 정보를 직접 달라고 요청한다
5. 빠진 내용을 `audit.md` 에 기록한다

### 사용자가 stage 를 다시 하길 원함

**상황**: 사용자가 stage 결과에 만족하지 않아 다시 하길 원함

**복구 단계**:
1. 다시 시작할지 사용자에게 확인한다 (데이터가 사라짐)
2. 기존 산출물 보관: `{artifact}.backup`
3. `aidlc-state.md` 의 stage 상태를 초기화한다
4. 계획 파일의 stage 체크박스를 비운다
5. stage 를 처음부터 다시 실행한다

### 사용자가 stage 를 건너뛰길 원함

**상황**: 사용자가 계획된 stage 를 건너뛰길 원함

**복구 단계**:
1. 사용자가 그 영향을 이해했는지 확인한다
2. 건너뛰는 이유를 `audit.md` 에 기록한다
3. `aidlc-state.md` 에 stage 를 "SKIPPED" 로 표시한다
4. 다음 stage 로 진행한다
5. 참고: 의존 항목이 빠지면 이후 stage 에서 문제가 생길 수 있음

## 상향 보고 (Escalation) 지침

### 사용자 도움을 요청할 때

**즉시**:
- 모순되거나 모호한 사용자 입력
- 필수 정보 누락
- AI 가 해결할 수 없는 기술적 제약
- 업무 판단이 필요한 결정

**해결을 시도한 뒤**:
- 같은 step 에서 반복되는 오류
- 복잡한 기술 문제
- 특이한 프로젝트 구조
- 외부 시스템과의 연동

### 처음부터 다시 하자고 제안할 때

**다음 경우 새로 시작을 고려**:
- 여러 stage 에 오류가 있음
- 상태 파일이 심하게 손상됨
- 사용자 요구사항이 크게 바뀜
- 아키텍처 결정을 뒤집어야 함
- 사용자가 빠진 정보를 줄 수 없음
- phase 간 산출물이 서로 맞지 않음

**다시 시작하기 전에**:
1. 기존 작업을 모두 보관한다
2. 배운 점을 기록한다
3. 남길 것을 정한다
4. 사용자 확인을 받는다
5. 새 실행 계획을 만든다

## 세션 재개 오류

### 재개 중 산출물 누락

**오류**: 이전 stage 의 필수 산출물이 없음
- **원인**: 파일이 삭제 · 이동되었거나 처음부터 만들어지지 않음
- **해결**: 
  1. 빠진 산출물을 만드는 stage 를 찾는다
  2. aidlc-state.md 에 그 stage 가 완료로 표시되었는지 확인한다
  3. 완료로 표시되었는데 산출물이 없으면: 그 stage 를 다시 실행한다
  4. 완료로 표시되지 않았으면: 그 stage 부터 재개한다
- **복구**: 빠진 산출물을 만드는 stage 로 돌아가 다시 실행한다

**오류**: 산출물 파일은 있지만 비었거나 손상됨
- **원인**: 쓰기 중단, 수동 편집, 파일 시스템 문제
- **해결**:
  1. 손상된 파일의 백업을 만든다
  2. 그 파일을 만드는 stage 에서 다시 생성을 시도한다
  3. 다시 만들 수 없으면: 재작성에 필요한 정보를 사용자에게 요청한다
- **복구**: 해당 산출물을 만드는 stage 를 다시 실행한다

### 재개 중 상태 불일치

**오류**: aidlc-state.md 에는 stage 완료로 나오지만 산출물이 없음
- **원인**: 상태 파일은 갱신되었지만 산출물 생성이 실패함
- **해결**:
  1. aidlc-state.md 에서 stage 를 미완료로 표시한다
  2. stage 를 다시 실행해 산출물을 만든다
  3. 완료로 표시하기 전에 산출물이 있는지 확인한다
- **복구**: stage 상태를 초기화하고 다시 실행한다

**오류**: 산출물은 있지만 aidlc-state.md 에는 stage 미완료로 나옴
- **원인**: 산출물 생성은 성공했지만 상태 갱신이 실패함
- **해결**:
  1. 산출물이 완전하고 유효한지 확인한다
  2. aidlc-state.md 에 stage 완료를 표시한다
  3. 다음 stage 로 진행한다
- **복구**: 실제 완료 상황을 반영하도록 상태 파일을 갱신한다

**오류**: aidlc-state.md 에 여러 stage 가 "current" 로 표시됨
- **원인**: 상태 파일 손상, 수동 편집
- **해결**:
  1. 산출물을 검토해 실제 진행 상황을 파악한다
  2. 실제로 어느 stage 에 있는지 사용자에게 묻는다
  3. aidlc-state.md 가 현재 stage 하나만 보이도록 고친다
- **복구**: 기존 산출물을 바탕으로 상태 파일을 다시 만든다

### 컨텍스트 불러오기 오류

**오류**: 이전 stage 에서 필요한 컨텍스트를 불러올 수 없음
- **원인**: 파일 누락, 내용 손상, 잘못된 파일 경로
- **해결**:
  1. 현재 stage 에 필요한 산출물을 나열한다
  2. 그중 누락되거나 손상된 것을 확인한다
  3. 누락된 산출물을 다시 만들거나 사용자에게 정보를 요청한다
- **복구**: 현재 stage 를 재개하기 전에 선행 stage 를 완료한다

**오류**: 불러온 산출물끼리 정보가 모순됨
- **원인**: 수동 편집, 여러 사람의 작업, 불완전한 갱신
- **해결**:
  1. 모순을 찾아 사용자에게 보여 준다
  2. 어느 정보가 맞는지 사용자에게 묻는다
  3. 모순이 해소되도록 산출물을 갱신한다
- **복구**: 진행 전에 모순을 정리한다

### 재개 모범 사례

1. **항상 상태 검증**: aidlc-state.md 가 실제 산출물과 맞는지 확인한다
2. **단계적으로 불러오기**: stage 별로 산출물을 불러오고 하나씩 검증한다
3. **빨리 멈추기 (Fail fast)**: 핵심 산출물이 없으면 즉시 멈춘다
4. **명확한 소통**: 무엇이 없고 왜 필요한지 사용자에게 정확히 알린다
5. **선택지 제시**: 다시 생성, 직접 제공, 새로 시작
6. **복구 기록**: 모든 복구 조치를 audit.md 에 기록한다
