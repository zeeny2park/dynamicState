# 내용 검증 규칙 (Content Validation Rules)

## MANDATORY (필수): 파일 생성 전 내용 검증

**CRITICAL (필수)**: 생성한 모든 내용은 파싱 오류를 막기 위해 파일에 쓰기 전에 반드시 검증한다.

## ASCII 도식 표준

**CRITICAL (필수)**: ASCII 도식이 들어간 파일을 만들기 전에는 어떤 파일이든:

1. `common/ascii-diagram-standards.md` 를 **불러온다 (LOAD)**
2. 각 도식을 **검증한다 (VALIDATE)**:
   - 줄마다 문자 수를 센다 (모든 줄은 반드시 같은 폭)
   - 다음만 사용: `+` `-` `|` `^` `v` `<` `>` 와 공백
   - Unicode 상자 그리기 문자 금지
   - 공백만 사용 (탭 금지)
3. 상자 모서리가 세로로 맞는지 확인해 정렬을 **테스트한다 (TEST)**

**패턴과 검증 체크리스트는 `common/ascii-diagram-standards.md` 참조.**

## Mermaid 도식 검증

### 필수 검증 단계
1. **문법 확인**: 파일을 만들기 전에 Mermaid 문법을 검증한다
2. **문자 이스케이프**: 특수 문자가 올바르게 이스케이프되었는지 확인한다
3. **대체 내용**: Mermaid 검증에 실패하면 텍스트 대안을 제공한다

### Mermaid 검증 규칙
```markdown
## Mermaid 도식이 들어간 파일을 만들기 전에:

1. 노드 ID 에 잘못된 문자가 없는지 확인 (영문자 · 숫자 + 밑줄만 사용)
2. 라벨의 특수 문자 이스케이프: " → \" 그리고 ' → \'
3. flowchart 문법 검증: 노드 연결이 유효해야 함
4. 간단한 검증으로 도식 파싱 테스트

## 대체 (FALLBACK): Mermaid 검증에 실패하면 텍스트 기반 워크플로우 표현 사용
```

### 구현 패턴
```markdown
## 워크플로우 시각화

### Mermaid 도식 (문법이 유효한 경우)
```mermaid
[validated diagram content]
```

### 텍스트 대안 (항상 포함)
```
Phase 1: INCEPTION
- Stage 1: Workspace Detection (COMPLETED)
- Stage 2: Requirements Analysis (COMPLETED)
[continue with text representation]
```

## 일반 내용 검증

### 생성 전 검증 체크리스트
- [ ] 포함된 코드 블록 검증 (Mermaid, JSON, YAML)
- [ ] 특수 문자 이스케이프 확인
- [ ] markdown 문법이 올바른지 확인
- [ ] 내용 파싱 호환성 테스트
- [ ] 복잡한 요소에는 대체 내용 포함

### 오류 예방 규칙
1. **도구 · 명령으로 파일을 쓰기 전에 항상 검증한다**: 검증하지 않은 내용은 절대 쓰지 않는다
2. **특수 문자를 이스케이프한다**: 특히 도식과 코드 블록에서
3. **대안을 제공한다**: 시각적 내용의 텍스트 버전을 포함한다
4. **문법을 테스트한다**: 복잡한 내용 구조를 검증한다

## 검증 실패 처리

### 검증에 실패하면
1. **오류를 기록한다**: 무엇이 검증에 실패했는지 기록한다
2. **대체 내용을 사용한다**: 텍스트 기반 대안으로 바꾼다
3. **워크플로우를 계속한다**: 내용 검증 실패 때문에 멈추지 않는다
4. **사용자에게 알린다**: 파싱 제약 때문에 단순화한 내용을 사용했다고 언급한다
